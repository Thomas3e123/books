Gravity SOP Foundry User Guide

Web Workspace · V15.4 hosted employee connection edition

How the system works

Build Room: Edit → Save → choose training → Review → Approve → Publish → Verify → Train → Sign off if required.

Employee Library: Find → Check revision → Read → Train if required → Pass knowledge check → Demonstrate if required → Follow the published procedure.

Approved is not published. Employees see only deliberately published SOPs. A passed knowledge check proves basic understanding; it does not replace manager hands-on competency verification when that requirement was selected.

Unsaved-change protection

If you change an SOP or recipe in the editor and choose Close or exit the page before saving, Foundry warns before discarding those edits. Use Save before leaving whenever the change should be kept.

Build Room directions — managers/editors

  1. Find the SOP. Open Build SOPs and search by title, task, station, or SOP ID.
  2. Edit the working copy. Choose Edit SOP. Replace sample/placeholders with the real restaurant process.
  3. Record the revision decision. Enter What changed / why. For a brand-new procedure use “Initial release.” Set an optional next review date.
  4. Choose training for this exact revision. Select one: (a) No additional training required, (b) Guided review + 5-question knowledge check, or (c) Guided review + knowledge check + manager hands-on sign-off. Gravity never makes this decision automatically.
  5. Save. A meaningful content change advances the revision and returns the SOP to Draft. The current employee copy stays unchanged.
  6. Review. Read the entire saved SOP. Verify equipment, quantities, safety, responsible role, checks, corrective action, and local requirements.
  7. Approve. Choose Mark approved and enter the approving manager name.
  8. Publish. Choose Publish to Employee Library. Until this step, employees still see the previous published revision or nothing.
  9. Verify. Open the Employee Library and confirm the title, revision, effective date, training requirement, and procedure.
  10. Train. Employees complete Train Me when required. Open Training Records to review scores and complete manager sign-off where required.

Import an existing SOP library

You do not have to replace good restaurant procedures with Gravity wording. Use Import / Export when your restaurant already has SOPs you trust and mainly needs revision control, training, publication, employee access, and history.

  1. Choose files, a folder, or paste an SOP. Gravity can convert structured/text formats where practical and places uncertain document/image formats into the Review Intake.
  2. Review the Import Queue. Confirm the title, station, and procedure text. The original source filename/format is retained with the working record.
  3. Handle duplicates deliberately. Skip a matching SOP, replace the matching working copy, or keep both.
  4. Save as Draft. Imported SOPs never become Approved or Published automatically.
  5. Complete any missing control fields. Confirm purpose, responsible role, when used, checks, corrective action, records, safety, training requirement, and what changed/why.
  6. Approve and Publish only after local review. Your restaurant decides whether the imported procedure is current, safe, complete, and appropriate.

Supported intake: Gravity transfer/JSON, CSV, TSV, TXT, RTF, HTML, DOCX, XLSX, ZIP/folder batches, copy/paste, plus review intake for PDF, legacy XLS, PNG, JPG/JPEG, WEBP, and HEIC. PDF/image/legacy XLS content must be confirmed or transcribed before saving because Gravity does not pretend uncertain extraction is reliable.

Export choices: Gravity transfer package, JSON, CSV, TSV, Excel-compatible workbook, Word-compatible document, RTF, TXT, HTML, Print/Save PDF, and ZIP bundle.

Hosted Employee Connection

The manager Build Room can connect its deliberately published employee material to a hosted restaurant workspace so employees can use the same Employee App from phones, home, work, or cellular data without being on the manager computer or the same Wi-Fi.

  1. Change the Employee Library PIN from the default 0000.
  2. Open Employee Connection in the Build Room and create the hosted restaurant workspace.
  3. Share the generated employee link or QR code. The link contains the restaurant code, never the Employee Library PIN.
  4. Publishing or withdrawing an SOP/recipe, changing an Active poster, or changing the Employee Library PIN triggers a hosted employee sync. The manager can also choose Sync Published Employee Library manually.
  5. Employee training, acknowledgments, questions/error reports, and learning activity can be pulled back into the manager workspace. Manager Inbox, Training Records, and Gravity Signals automatically pull new hosted records when opened.

Boundary: working drafts, unapproved revisions, manager PINs, manager-only notes, backups, and Gravity Signals are not sent to the hosted employee workspace. A Gravity Signal remains an indicator, not a conclusion.

Employee Library directions — employees

  1. Find the task. Search or choose your station.
  2. Open the SOP. Check the revision and effective date before starting.
  3. Read the current procedure. Do not use an old printed copy when the library shows a newer revision.
  4. Check the training box. It tells you whether training is required for this revision and what changed.
  5. Choose Train Me when required. Read the SOP one section at a time.
  6. Take the 5-question knowledge check. You need 80% to pass. If you miss questions, review the displayed correct answers, reread the SOP, and retry.
  7. Acknowledge the revision. Passing records the exact SOP revision you reviewed.
  8. Demonstrate the task if required. When the SOP requires manager sign-off, training is not complete until a manager approves your hands-on demonstration.
  9. Ask when unsure. Use Ask a question / Report an error for routine follow-up. For an immediate safety, guest, product, or equipment issue, contact the manager on duty directly.

Needs Attention dashboard

The Build Room home screen highlights manager action instead of making you hunt for it. It shows approved revisions not current in the Employee Library, manager competency sign-offs waiting, failed knowledge-check attempts, open employee messages, and published SOPs with overdue review dates.

Food recipes and bar drinks

Food Recipes and Bar Drink Recipes remain separate and now use the same control idea as SOPs: Edit → Save → Review → Approve → Publish → Verify. Approval alone does not change the Employee Library copy.

  • Use the direct Import button for CSV/JSON batches, up to 100 recipes / 2 MB per batch.
  • Working recipes keep revision history. Record What changed / why before approval.
  • Use Mark approved, then Publish to Employee Library, then open the employee copy and verify it.
  • Build Room recipes have direct Print preview. The preview should show the full recipe, not branding alone.
  • Bar drink records support exact ingredients, serving size/yield, glassware/service vessel, ice, build method/order, garnish, allergens, and notes.
  • Use duplicate handling deliberately: keep the existing version or replace it.

Revision history and published copies

Editing a working SOP never silently changes the published employee snapshot. Previous stored revisions remain read-only in Revision History. Publishing replaces the employee snapshot only after the working copy is saved and approved. Withdraw removes the employee copy while leaving the working SOP available for correction.

Employee messages

Employees can send a linked question or error report from an SOP or recipe. Managers review these under Employee Messages. A saved message is not an emergency alert and does not prove a manager has read it. Resolve the message only after the question was answered or the correction was communicated.

Employee App and cross-station growth

The Employee App is the employee starting point. A home/current station may be selected for the current employee session for convenience, but it never restricts access. Employees can open All SOPs or Explore Other Stations at any time. A view or training start is not certification, a transfer request, or permission to work a station.

Employee identity is optional for browsing. A home/current station is used only to make the employee experience more convenient; it does not restrict access to other stations.

Gravity Signals

Gravity Signals is optional, manager-only decision support. On first use the manager chooses whether to enable it. The restaurant can later turn the master switch off, disable categories, or disable individual Signal types. Turning Signals off stops manager-side Signal calculation and pattern interpretation; required operational records such as training completion, acknowledgments, quiz records, and employee questions continue normally.

A Signal is an indicator, not a conclusion. Examples include several employees struggling with the same knowledge-check material, multiple questions or error reports around one procedure, a possible documentation gap, or a possible cross-training opportunity. Managers must verify the circumstances before acting.

Why manager-only: employees should learn naturally. If employees know the exact internal pattern logic, they may avoid rereading an SOP or asking a question because they fear creating a flag, or deliberately use material to try to create a development Signal. Employees therefore do not see Signal scores, internal logic, or interpretation tools.

Open the Gravity Signal Interpretation Map for possible system causes, possible people/training causes, what to verify next, and what not to assume.

Poster Library

The Poster Library includes 178 editable operational templates across 15 categories, including blank posters, food safety, cleaning/sanitation, safety, operations, service, bar/alcohol, emergency, training, technology, kitchen reference/legends, equipment, station setup, portion/recipe, and people/communication. SOPs suggest relevant poster templates, posters suggest related published SOPs, and managers decide which relationships to save. Saved poster changes advance the poster revision and archive the prior saved version. Posters can be Active or Retired and print in portrait or landscape. Required legal/government notices must come from the applicable authority rather than an editable Foundry template.

Backups and recovery

  1. Before a major editing session, browser reset, device change, or restore, open Restaurant branding & backups.
  2. Choose Download full backup and save the JSON file in a protected location outside the browser.
  3. The full backup carries working SOPs, published SOPs, recipes, revision history, training records/sign-offs, messages, posters, branding, room settings, and manager-only signal evidence stored by this workspace.
  4. After a restore, verify representative SOPs, recipes, training records, messages, posters, and the Employee Library before relying on the restored workspace.

Website working data is stored locally in this browser. Clearing site data can remove it, so backups remain important.

QR codes and website links

Before a hosted connection is created, QR destinations point to the local website Employee Library. After the restaurant creates Hosted Employee Connection, SOP and poster QR destinations use the restaurant-coded hosted employee access path so a phone can reach the current published material from any internet connection. The PIN is never printed inside the QR. Test every posted QR with the device employees will actually use before relying on it.

Control rules

  • Never treat a Gravity sample as approved restaurant policy without local review.
  • Never assume Approved means Published.
  • Never let a quiz replace physical demonstration when the task requires competency verification.
  • Never let Gravity decide whether retraining is needed. The responsible manager/revisor selects the training requirement for each revision.
  • For urgent safety or operational problems, contact the manager on duty instead of waiting for an inbox response.
